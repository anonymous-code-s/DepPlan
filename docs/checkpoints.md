# Strategy checkpoints

Each strategy GCN receives concept embeddings and graph adjacency from its associated structure source. Its output classes are `sequential`, `parallel` and `hierarchical`, in that order.

| Strategy-classifier directory | Graph-source configuration |
|---|---|
| `SPRING` | [SPRING](https://github.com/SapienzaNLP/spring), using the [amrlib `parse_spring` interface](https://github.com/bjascob/amrlib-models) |
| `cail` | amrlib `parse_gsii`, `model_parse_gsii-v0_1_0` |
| `t5_base` | amrlib `parse_xfm`, `model_parse_t5-v0_2_0`, T5-base |
| `graphene` | Graphene support-based ensemble of CAIL, T5-base and SPRING; support threshold 0.5 |
| `GPT-4o-mini` | [GPT-4o-mini](https://developers.openai.com/api/docs/models/gpt-4o-mini), API model ID `gpt-4o-mini`, generating PENMAN AMR from question text |

Each directory contains a strategy GCN for the graph source listed above. We use `spring` and `gpt4o_mini_amr` as the source keys for the `SPRING` and `GPT-4o-mini` directories in configurations, sample manifests and classification results. The linked parser references describe the external models used to produce the input graphs.

The GPT-4o-mini AMR-generation configuration uses temperature 0, a 1,536-token output limit, seed 42, up to two AMR syntax repairs and up to three transport attempts per request. Graph status is recorded in the sample manifests. All five sources share the silver labels generated by Qwen2.5-32B-Instruct from question text and reference SPRING AMRs.

The classifiers use AdamW with learning rate 0.001 and weight decay 0.01, batch size 16, dropout 0.2 and 30 epochs. Inference uses the final-epoch checkpoint. Each `config.json` records the architecture and optimizer settings. `retraining_seed: 2026` sets the default for new training runs.

## Weight format

Each directory contains:

- `model.safetensors`: ten named parameter tensors, 139,907 parameters in total.
- `config.json`: label order, encoder, architecture, training configuration and digests.
- `training_history.json`: recorded epoch, loss and training accuracy.

Safetensors stores the parameter tensors and graph-source metadata; model configuration is kept in JSON.

`checkpoints/manifest.json` and each `config.json` record `weights_sha256`, computed
from the distributed `model.safetensors` bytes.

[source_provenance.json](../checkpoints/source_provenance.json) records the official reference for each graph source together with the classifier file and tensor-payload digests.

SHA-256 checksums for the SPRING and GPT-4o-mini classifier files:

| Classifier | SHA-256 of `model.safetensors` |
|---|---|
| `SPRING` | `1a61ed2721c3db524d99c74c7030b364d8b8353e6c9dccba91fda9f908f2c662` |
| `GPT-4o-mini` | `bed74f59e39b3076246d395d23d8cfcc22b6c85ed2e00bbb15fd48446c088c3d` |

To recompute these values:

```bash
sha256sum checkpoints/SPRING/model.safetensors checkpoints/GPT-4o-mini/model.safetensors
```

## External model interfaces

Each checkpoint contains the projection, two GCN layers and the classification MLP. The encoder, parser and language model are supplied through separate interfaces.

| Interface | Model | Where to obtain it |
|---|---|---|
| `--checkpoint checkpoints/SPRING` | Strategy GCN for SPRING graphs | Included in `checkpoints/SPRING` |
| `--encoder` | BGE encoder | External model ID or local model directory |
| `parse-amr --model-dir` | AMR parser | Local parser model directory |
| `run-qa --base-url` | Language model | OpenAI-compatible inference service |

The classifier receives AMR triples and uses the external BGE encoder to construct node features. It outputs a sequential, parallel or hierarchical strategy. Producing AMR graphs requires the separate parser interface.

## Interpreting the reported metrics

Classification accuracy and Macro-F1 measure agreement with silver labels. Recompute them from `results/classification/*.jsonl`, or run inference on source-matched AMR graphs prepared from the question IDs in the manifests.

Smatch measures parser quality against gold AMRs. In our paper, we report corpus-level scores for each dataset and their sample-weighted mean. See [evaluation inputs](data.md#evaluation-inputs) for the data required for each evaluation.
